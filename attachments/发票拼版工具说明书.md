# 电子发票自动拼版与打印工具 — 项目需求文档 / Hermes Agent 开发任务书

## 0. 文档目的

本文档用于指导 Hermes Agent 基于现有原型 `发票拼版工具UI.html`，开发一个可实际使用的电子发票整理、拼版、预览与打印工具。核心目标是：

1. 支持上传 PDF、图片、OFD、XML 等电子发票文件。
2. 支持每页 A4 打印 2 张、3 张、4 张发票。
3. 支持发票排序、金额统计、打印预览、剪切线、报销汇总表。
4. 默认在浏览器本地处理，保护用户隐私。
5. 打印结果符合单位报销贴票习惯。

---

## 1. 背景与目标

日常报销时，员工需要将电子发票打印到纸质 A4 纸上，再裁剪、粘贴到报销单。很多单位要求一张 A4 纸打印多张发票，以节省纸张并统一格式。

现有原型已经具备：

- 上传 PDF / PNG / JPG。
- PDF 首页渲染为缩略图。
- 每页 1 / 2 / 3 / 4 张拼版。
- A4 实时预览。
- 拖拽排序。
- 金额编辑与汇总。
- 剪切虚线、贴票边框、报销汇总表。
- 浏览器打印。

本项目的目标是：在现有原型基础上，补齐真实发票解析能力，重点增加 OFD 和 XML 格式支持，并将代码重构为可维护、可测试、可扩展的项目。

## 2. 目标用户与使用场景

### 2.1 目标用户

- 需要报销的上班族。
- 企业财务、行政人员。
- 需要批量整理电子发票的个人或小团队。

### 2.2 典型场景

1. 用户收到多张 PDF、OFD、XML、图片格式电子发票。
2. 用户打开网页，批量上传发票。
3. 系统自动解析并生成缩略图、发票号码、日期、金额等元数据。
4. 用户拖拽调整顺序，选择“每页 2 张 / 3 张 / 4 张”。
5. 用户在 A4 预览区确认排版。
6. 用户点击打印，浏览器输出 A4 拼版文档。
7. 用户裁剪后贴票报销。

## 5. 功能需求

### 5.1 文件上传

- 支持点击上传和拖拽上传。
- `accept` 至少包含：
  - `.pdf`
  - `.ofd`
  - `.xml`
  - `image/png`
  - `image/jpeg`
- 单文件建议限制：20MB。
- 单次建议限制：100 张。
- 上传后立即进入解析队列。
- 解析失败时，列表中显示错误状态，不阻塞其他文件。

### 5.2 格式解析

#### 5.2.1 PDF

- 使用 `pdf.js` 渲染首页为缩略图。
- 可选：提取 PDF 文本，尝试匹配：
  - 发票号码
  - 开票日期
  - 价税合计
  - 销售方名称
  - 购买方名称
- 如果无法可靠提取金额，允许用户手动编辑。
- 多页 PDF：默认取第一页，后续可增加页码选择。

#### 5.2.2 图片

- PNG / JPG / JPEG 直接生成预览。
- 无法自动解析金额时，默认金额为 0，用户手动填写。
- 图片按比例缩放，保持清晰度。

#### 5.2.3 OFD

OFD 是电子发票常见标准格式，本质是 ZIP 包，内部包含 XML 和版式信息。

实现策略：

1. 优先前端解析：
   - 评估并接入 `ofd.js`、`ofd-parser` 或同类库。
   - 将 OFD 首页渲染为 canvas，再转为 dataURL。
   - 提取文本内容，尝试匹配发票号码、日期、金额。
2. 如果前端库不满足：
   - 可降级为服务端转换，但默认仍应本地处理。
3. 如果 OFD 加密或解析失败：
   - 显示“OFD 解析失败，请手动上传截图或填写金额”。
4. 验收要求：
   - 常见增值税电子发票 OFD 可渲染出缩略图。
   - 金额可手动修正。

#### 5.2.4 XML

XML 发票通常是结构化数据，解析成功率最高。

实现策略：

1. 使用 `DOMParser` 解析 XML。
2. 兼容不同命名空间和字段名。
3. 建立字段映射表：

| 目标字段 | 可能字段名 |
|---|---|
| 发票号码 | InvoiceNumber、InvoiceNo、发票号码、FpHm |
| 开票日期 | IssueDate、InvoiceDate、开票日期、KprQ |
| 价税合计 | TotalTaxIncludedAmount、TaxInclusiveTotalAmount、价税合计、Jshj |
| 销售方 | SellerName、销售方名称、XsfMc |
| 购买方 | BuyerName、购买方名称、GfMc |
| 项目名称 | ItemName、货物或应税劳务名称、Hwmc |

4. 解析成功后，使用统一模板生成发票卡片预览：
   - 标题：电子发票
   - 发票号码
   - 开票日期
   - 购买方
   - 销售方
   - 金额
   - 明细表格
5. 如果字段缺失：
   - 显示原始 XML 关键内容。
   - 允许用户手动补充金额和发票号。

### 5.3 发票列表与编辑

每张发票在左侧列表显示：

- 拖拽手柄。
- 缩略图。
- 文件名。
- 文件类型。
- 金额输入框。
- 删除按钮。

支持：

- 拖拽排序，排序结果影响打印顺序。
- 修改金额后，总金额自动更新。
- 删除单张发票。
- 清空全部。
- 载入示例数据。

### 5.4 拼版设置

必须支持：

- 每页 1 张。
- 每页 2 张。
- 每页 3 张。
- 每页 4 张。

可选设置：

- 页边距：5mm - 25mm。
- 卡片间距：2mm - 20mm。
- 显示剪切虚线。
- 显示贴票引导边框。
- 显示底部报销汇总表。
- 纸张方向：纵向 / 横向。

### 5.5 A4 实时预览

- 使用屏幕 A4 比例：约 595px × 842px。
- 显示当前页 / 总页数。
- 支持上一页、下一页。
- 根据每页张数动态计算网格：
  - 1 张：1×1。
  - 2 张：上下 1×2。
  - 3 张：上下 1×3。
  - 4 张：2×2。
- 发票图片使用 `object-fit: contain`，保持比例，不拉伸。
- 预览内容必须与打印内容一致。

### 5.6 打印

- 点击“立即打印”后，生成所有 A4 页面。
- 使用 `window.print()`。
- `@media print` 隐藏所有非打印元素。
- `@page` 设置：
  - `size: A4 portrait;`
  - `margin: 0;`
- 每个 `.a4-page`：
  - 宽 210mm，高 297mm。
  - `page-break-after: always;`
- 打印时：
  - 不显示按钮、导航、侧边栏。
  - 不显示页眉页脚。
  - 保留剪切线、边框、汇总表。
- 如果选择横向：
  - `@page { size: A4 landscape; }`
  - 预览和打印同步切换。

### 5.7 金额统计

- 每张发票金额可编辑。
- 自动计算：
  - 发票总张数。
  - 报销合计总金额。
  - 每页小计。
- 金额格式：`¥ 0.00`。
- XML、OFD、PDF 能解析出金额时自动填充；否则为 0，等待手动输入。

### 5.8 报销汇总表

可选显示在每页底部：

- 序号。
- 发票名称 / 用途。
- 金额。
- 本页小计。
- 本页张数。

注意：

- 每页 4 张时，汇总表可能占用过多空间，建议默认关闭或使用紧凑样式。
- 用户可手动开关。

## 6. 排版与打印规则

### 6.1 A4 尺寸

- 纵向：210mm × 297mm。
- 横向：297mm × 210mm。
- 屏幕预览按比例缩放，打印时使用真实 mm。

### 6.2 每页 2 张

- 上下排列。
- 每张发票占约半页高度。
- 适合大多数电子发票。

### 6.3 每页 3 张

- 上、中、下排列。
- 每张高度约为 A4 的三分之一。
- 需要确保发票内容不被压缩变形。
- 如果发票太高，可提示用户改用 2 张/页。

### 6.4 每页 4 张

- 2×2 网格。
- 适合小尺寸发票或行程单。
- 汇总表建议关闭。

### 6.5 剪切线

- 使用虚线边框。
- 可在卡片边缘显示剪刀图标。
- 打印时保留。

## 7. 技术架构建议

### 7.1 总体方案

优先纯前端实现：

- HTML + CSS + JavaScript。
- Tailwind CSS 保持现有风格。
- FontAwesome 图标。
- PDF.js 解析 PDF。
- Sortable.js 拖拽排序。
- OFD 解析库：评估 `ofd.js` 或同类库。
- XML：浏览器原生 `DOMParser`。
- 文件打包：OFD 可能需要 `JSZip`。

如果 OFD 前端解析不稳定，可增加可选 Node 服务，但默认不上传文件。

## 9. 验收标准

### 9.1 功能验收

- 能上传 PDF、OFD、XML、PNG、JPG。

- PDF：至少首页可预览。

- XML：能解析出金额、发票号、日期等字段。

- 打印结果每页为 A4。
- 无页眉页脚。

- 损坏文件提示错误。
- 不支持的格式提示。
- 大文件提示。
- 解析失败不崩溃。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| OFD 前端解析库兼容性差 | OFD 无法预览 | 评估多库，必要时服务端转换或降级提示 |

| 大文件卡顿 | 页面无响应 | 限制大小、异步解析、缩略图压缩 |
| 4 张/页空间不足 | 发票变形 | 保持比例，提示用户切换 2 张/页 |

## 13. 最终产品定义

这是一个“本地优先”的电子发票拼版打印工具：

- 用户上传发票。
- 系统解析并预览。
- 用户排序、改金额、选每页张数。
- 系统生成 A4 拼版。
- 用户一键打印。
- 裁剪后贴票报销。

核心关键词：**多格式、本地处理、自动拼版、A4 打印、报销友好、简单快速。**
